# Hiring Manager Guide

## What this portfolio is intended to demonstrate

This portfolio is designed to answer four questions a technical interviewer may have:

1. Can the candidate work with real security telemetry?
2. Can the candidate reason through an investigation instead of only running tools?
3. Can the candidate document what happened and communicate risk clearly?
4. Does the candidate distinguish verified evidence from assumptions?

## Best starting points

### Technical depth
Open **Lab 01 — Microsoft Sentinel Detection & Incident Investigation** and review:

- detection queries;
- evidence files;
- analyst notes;
- incident timeline;
- MITRE ATT&CK mapping;
- remediation recommendations.

### Breadth
Review Labs 02–08 to see the planned expansion into Active Directory, vulnerability management, web application security, network analysis, DFIR, purple teaming, and security automation.

### Architecture and executive communication
Review the separate repositories:

- **Project Iron Curtain** — enterprise risk, security architecture, control mapping, incident response, Secure SDLC.
- **Project Guardian Angel** — AI security, governance, data protection, responsible AI, monitoring, audit, human oversight.

## Portfolio quality standards

- No fabricated screenshots.
- No copied scanner output presented without analysis.
- No production claims for academic architectures.
- No simulated attack represented as a real compromise.
- Findings should contain evidence, impact, remediation, and validation/retest criteria.
- Every completed lab should state its scope and limitations.
